# V6b 画素を持たないレイヤー（色調補正・グラデーション・べた塗り）の CSP での確認

色調補正レイヤー、グラデーションレイヤー、べた塗りレイヤーは画素を保存しない。
CSP はファイルを開くときに、設定（`Layer.FilterLayerInfo`、`Layer.GradationFillInfo`）から描き直す。
そこで、設定を 1 つずつ変えたファイルを生成し、CSP で書き出した PNG とこのライブラリの描画を比べて、規則を決めた（R10）。

使ったのは生成した検査用のファイルだけで、作品ファイルの画素は使っていない。
コーパス（V1）からは、設定の種類と値の分布だけを集計した（作品の中身は含まない）。

## 1. 色調補正レイヤー（`Layer.FilterLayerInfo`）

形式は `u32 種類, u32 大きさ, 設定`（ビッグエンディアン）。種類ごとの設定は `src/correction.rs` の冒頭に書いた。
画素の色（ストレート、0〜255）に次の式を当て、レイヤーの不透明度とマスクで下の画像と混ぜる（通過のフォルダーと同じ扱い）。

| 種類 | 規則 |
|---|---|
| 1 明るさ・コントラスト | k = 1/(1 − c/100)（c > 0）、1 + c/100（c ≤ 0）。c > 0 では (v + b − 127.5)·k + 127.5、c ≤ 0 では (v − 127.5)·k + 127.5 + b。c = 100 は v + b > 127.5 で 255 |
| 2 レベル補正 | 入力の黒・白、ガンマ点、出力の黒・白。色ごとの表のあとにマスターの表 |
| 3 トーンカーブ | 制御点を制御多角形とする、端を固定した一様 2 次 B スプライン。色ごとのカーブのあとにマスター |
| 4 色相・彩度・明度 | 明度 → 色相 → 彩度の順。色相は HSL の色相を回す（S と L は保つ）。彩度 −t は v を保って彩度を下げたあと全体を 1 + t·s/2 倍（−100 で灰色）。彩度 +t は色相を保ったまま HSV の s と v を同じ量だけ上げる（上限で止まる）。明度 −t は c·(1 + t)、+t は v を 255 に近づけ s を同じ割合で下げる |
| 5 カラーバランス | 下記 |
| 6 階調の反転 | 255 − v |
| 7 ポスタリゼーション | floor(floor(v·n/256)·255/(n − 1)) |
| 8 2 値化 | (306R + 601G + 117B) >> 10 ≥ しきい値で白 |
| 9 グラデーションマップ | Rec.601 の輝度（0.299, 0.587, 0.114）の位置のグラデーションの色。混色はグラデーションと同じ |

### カラーバランス

設定は `i32 輝度を保つ, シャドウ R G B, 中間調 R G B, ハイライト R G B`（−100〜100）。どちらの場合も、各チャンネルが自分の入力だけで決まる表になる（格子の背景で確認、チャンネルをまたぐ影響はない）。

輝度を保たない場合は、チャンネルごとに黒点・白点・ガンマを持つ経験式で近似した（±30・±50・±100 の各設定で 3 以内）。係数は `balance()` にある。

輝度を保つ場合の規則（差 1 以内）:

- シャドウ: 黒点 = 自分の負の量 + 他の 2 チャンネルの正の量。R シャドウ +50 は G と B の黒点を 50 にし、R は変えない
- ハイライト: 白点 = 255 − (自分の正の量 + 他の 2 チャンネルの負の量)
- 中間調: ガンマ = exp(−0.0064·(自分の量 − 3 チャンネルの平均))
- 出力 = 255·((v − 黒点)/(白点 − 黒点))^ガンマ

2 チャンネル以上を同時に動かした場合の合わせ方（足し算）は推測で、まだ確かめていない。

## 2. グラデーション（`Layer.GradationFillInfo`、グラデーションマップの `GradationData`）

### ストップと補間の曲線

- 2 つのストップの間は、ストップのフラグ 0x10 があれば保存された制御点の曲線、なければ CSP の既定の S 字曲線（(0, 0), (0.25, 0.1), (0.75, 0.9), (1, 1) の 2 次 B スプライン、1/4 の位置で 17.8%）で混ぜる
- 透明度 0 のストップは、混ぜる相手のストップの色を使う（色は変わらず、透明度だけが下がる）。透明度が 0 でなければストレートの色のまま混ぜる
- べた塗りは `GradationSettingAdd0001` の 2 語目が 1 で、最初のストップの色で塗る

### 混色の方法（`GradationData` のヘッダーが 24 バイトのとき、20 バイト目が方法、24 バイト目が輝度補正）

| 値 | CSP の表示 | 規則 | 最大差 |
|---|---|---|---|
| 0（16 バイトのヘッダーも） | 通常 | sRGB の値をそのまま混ぜる | 3 |
| 2 | 知覚的（Photoshop 互換） | Oklab で混ぜる | 3 |
| 3 | リニア（Photoshop 互換） | リニアの光で混ぜる | 5 |
| 1 | 知覚的 | CSP 独自の顔料のような混色。近似（下記） | 3〜135 |

輝度補正は知覚的（1）のときだけ効く。

知覚的（1）で分かったこと:

- 黒 → 白は暗い側に寄る。Oklab の明度で見ると、白の重みが黒の r 倍になる形でよく合う。r は輝度補正 0〜3 で 0.195、0.30、0.40、0.51（0.195 + 0.104 × 補正）。中央の値は 13、27、41、55
- 白 → 黒は黒 → 白を反転した形になる（重みは色の暗さで決まり、向きによらない）
- 色どうしでは、重みの比が位置によって変わる。また、赤 → 青のように途中で明度が両端より下がる組がある。スペクトル（Kubelka–Munk、spectral.js）、RGB・LMS ごとの Kubelka–Munk、Oklab・Lab・リニアの直線補間を試したが、どれも合わなかった

描画では Oklab で混ぜ、重みを r^(明度の差) で寄せる近似を使う。灰色では 2〜15、色どうしでは数十の差が残る。
コーパスでは、知覚的のグラデーションレイヤーが 194 枚（全 3,249 枚の 6%）ある。

### 形

`GradationSetting` は `u32 ?, u32 形, u32 ?`、楕円の幅・高さ・回転、始点・終点（f64）。

- 形 0（直線）: 始点から終点への射影
- 形 1（円）: 始点を中心とする、半径が楕円の幅の半分の円。幅 300・高さ 100 で回転 0° と 45° のファイルが同じ円（半径 150）になった。CSP は高さと回転を使っていない
- コーパスでは、幅の半分 = 始点から終点までの距離、回転 = 始点 → 終点の向きになっていて、高さはキャンバスの大きさのことが多い
- 始点・終点はレイヤーのオフセット（`LayerOffsetX/Y`）からの相対。移動したグラデーションレイヤーでは足して使う（V6 5.4）
- グラデーションレイヤーが画素を保存していることがあるが、設定から描く（保存された画素は古いことがある、V6 5.4）
- 1 語目（0・2・3）と形 2 の意味は未確認

## 再現の手順

```sh
# CSP で、上の「ひな形」のファイル TEMPLATE.clip を作る
cargo run --release -p csp-lab --example corr_test -- TEMPLATE.clip made           # round1
cargo run --release -p csp-lab --example corr_test -- TEMPLATE.clip made round4    # round2〜4 も同様
# 各 made/corr_X.clip を CSP で開き、「画像を統合して書き出し → .png」で made/corr_X_csp.png を書き出す
cargo run --release -p csp-lab --example render_compare -- made/corr_X.clip made/corr_X_csp.png
```
