# V1 コーパス検証

ユーザーの PC にある実ファイル（CLIP STUDIO PAINT で保存された作品）すべてに対して `cspf corpus` を実行した結果。
元ファイルは読み取りだけで、変更していない（制約 C2）。ここに載せるのは件数の集計だけで、作品の中身（画素・文字・レイヤー名・パス）は含まない（N6）。

## 実行条件

| 項目 | 値 |
|---|---|
| 実施日 | 2026-10-24 |
| 対象 | `.clip` 719 件（合計 22.98 GiB）、`.cmc` 42 件 |
| 実行環境 | ユーザー PC 上の Linux VM、`x86_64-unknown-linux-musl` の静的バイナリ、2 並列 |
| 所要時間 | 約 1,505 秒（1 ファイルあたりの合計、全項目の検査込み） |
| コマンド | `cspf corpus ROOT OUT.jsonl --shard K/2 --list LIST.txt`（既定の検査をすべて有効） |

検査の中身は `crates/csp-format/src/verify.rs` の `check_clip` / `check_cmc`。

### R6 の内訳: 圧縮設定

| 圧縮設定 | ブロック数 | 対象 |
|---|---|---|
| zlib level 1・windowBits 15・**memLevel 9** | 1,859,078 | レイヤー・マスク・ミップマップ・サムネイルなど CSP が描いた画素 |
| zlib level 6・windowBits 15・memLevel 8（zlib の既定） | 44 | `BrushPatternImage`（素材から取り込んだブラシ先端画像）。素材のブロックがそのまま入っている |
| どちらとも不一致 | 0 | |

memLevel 9 は zlib の既定（8）と違い、Rust の zlib 実装（miniz_oxide・zlib-rs）では同じバイト列にならない。このため圧縮だけ C の zlib（`libz-sys`）を使う（`crates/csp-format/src/zlib.rs`）。

## 再現方法

```sh
cargo build --release -p cspf
cspf corpus ROOT out.jsonl --shard 0/2 &   # 2 並列の例
cspf corpus ROOT out2.jsonl --shard 1/2 &
```

`out.jsonl` は 1 ファイル 1 行の報告（パスは ROOT からの相対）で、途中で止めても同じコマンドで続きから再開できる。
報告の JSON にはパスが入るため、リポジトリには入れず、この文書のような集計だけを残す。
