# V9 CSP の版の違い

CSP の新旧の版とグレード（PRO / EX / DEBUT）で、保存されるファイルがどう違うかを調べ、
このライブラリが全世代のファイルを読み書きできるかを確かめた記録。仕様は [09 章](../spec/09-versions.md)。

作品ファイル（コーパス）は読むだけで、変えていない。CSP で開いたのは、作業フォルダーに作った写しと検査用のファイルだけ。
ファイルはリポジトリに入れない。

## 実施条件

| 項目 | 値 |
|---|---|
| 実施日 | 2026-10-25 |
| CSP | CLIP STUDIO PAINT EX 5.1.4（Windows、`CLIPStudioPaint.exe` のファイルバージョン 5.1.4.0）。ユーザーの PC で Computer use により操作 |
| コーパス | `.clip` 719 件・`.cmc` 42 件（保存日 2017-08〜2026-10） |
| 道具 | `tools/corpus/version_census.py`（構造の集計、標準ライブラリだけ）、`cspf version`、`examples/version_probe.rs` |

## 1. コーパスの集計

`version_census.py` で、全 761 件の表・列・`ParamScheme` の全行・SQLite のヘッダー・版らしい列の値を集計した（作品の中身は出さない）。

- 版の番号を持つ値はない。`Project.ProjectInternalVersion` は全件 `"1.1.0"`、コンテナのヘッダーも全件同じ
- SQLite のヘッダーで違うのは、最後に書いた SQLite の版だけ（760 件が 3.30.1、2017 年の 1 件が 3.8.8）
- `ParamScheme` の登録の集合は、保存日の順にきれいに並ぶ 12 の世代に分かれる（09 章の表）。世代の判定は、各世代で増えた列の「目印」で行う
- グレードを記録する列はない

`cspf version` を PC 上で全 761 件に実行した: エラー 0 件。世代の内訳は 09 章の表のとおりで、どの世代にも当てはまらないのは 2017 年の 1 件だけ。
`resaved`（古い版で作って新しい版で保存し直した）は 45 件で、内訳は末尾に行が足された 33 件（`.clip` 26、`.cmc` 7）と、
3.0 以降で保存し直して、登録をやめた列が残っている 12 件。

## 2. 古い世代のファイルを CSP 5.1.4 で開く・保存する

### 2.1 古い世代の写しの編集

コーパスから、1.8〜2.x の 7 世代（2020〜2024 年）のファイルを 1 件ずつ作業フォルダーに写し、このライブラリで赤い四角のラスターレイヤー
「ver_gXX」を一番上に足した。どれも登録（`ParamScheme`）は変わらず、`cspf version` の世代は元のまま。

| 写し | 世代 | CSP 5.1.4 で開く | 足したレイヤー |
|---|---|---|---|
| g08_edit | 1.8〜1.10.3 | 開けた（警告なし） | 一番上に表示 |
| g09_edit | 1.10.5〜1.10.9 | 開けた（警告なし） | 一番上に表示 |
| g10_edit | 1.10.10〜1.11 | 開けた（警告なし） | 一番上に表示 |
| g11_edit | 1.11〜1.12 | 開けた（警告なし） | 一番上に表示 |
| g12_edit | 1.12〜1.13 | 開けた（警告なし） | 一番上に表示 |
| g13_edit | 2.0 | 開けた（警告なし） | 一番上に表示 |
| g14_edit | 2.1〜2.x | 開けた（警告なし） | 一番上に表示 |

### 2.2 CSP 5.1.4 で保存すると

g08_edit（1.8〜1.10.3、登録 1,103 行）で表示を 2 回切り替えて上書き保存した。確認の画面は出なかった。保存後のファイルは:

- `ParamScheme` は 1,256 行の 1 つの塊。5.1.4 の新規ファイル（1,255 行）と同じ列が同じ `_PW_ID` にあり、
  加えて古いファイルにあった `CameraInfo.CameraZoomWithDolly` が `_PW_ID` 353 に残る。元の行で消えたものはない
- 表 `ParamScheme` は作り直され、`AlternativeLockType`・`AlternativeLockSpecified` が `LinkTable` の前にある（`ALTER TABLE` ではない）
- `cspf version` は `saved_by` 5.1。`created_by` は、作り直しで分からなくなるため、この結果を受けて `None` にした（`resaved` は真）

5.x で増えた登録 16 列を消した写し（`version_probe` の `older`、CSP 5.1.4 が保存した検査用のファイルから作成）も、開いて上書き保存した。
確認の画面は出ず、消した行が新規ファイルと同じ `_PW_ID`（例: `BrushStyle.WaterEdgeStyle` 952、`Layer.Has1_0_19` 236）に戻った。

コーパスでは、2.x までの保存は末尾に足し、3.0 以降の保存（11 件の `.clip` と 4.2 の 1 件）は作り直している。
`.cmc` は 4.2 の保存でも末尾に足している。

## 3. バージョン互換情報の保存

[環境設定] → [ファイル] の「バージョン互換情報の保存」（既定は「保存しない」）。色調補正 9 種・グラデーション・べた塗り 2 枚を含む検査用の
512×512 px のファイルを開き、「保存する」で別名保存（`compat_on`）、「保存しない」に戻して別名保存（`compat_off`）した。設定は元の「保存しない」に戻した。

| 項目 | 保存しない | 保存する |
|---|---|---|
| ファイルの大きさ | 1,360,501 バイト | 1,636,665 バイト |
| 外部チャンク | 96 個 | 109 個 |
| `Canvas.CanvasRenderMipmapForceSaved` | 0 | 1 |
| 表・列・登録 | — | 同じ |

増えた 13 個の外部チャンクは、用紙・グラデーション・べた塗り 2 枚・色調補正 9 枚の、描画結果のミップマップ（`Layer.LayerRenderMipmap`）の
100% の段の Offscreen に入る画素。「保存しない」では、これらの Offscreen はブロックの中身を持たない。ほかの行の違いは
`CanvasWorkTime` と、保存ごとに変わる外部チャンクの ID だけ。

## 4. 知らない列を含むファイル

`version_probe` で、CSP 5.1.4 が保存した検査用のファイルの一番上のラスターレイヤーに、5.1.4 が知らない列 `Layer.Has1_0_99` を足した 6 種類を作り、
CSP 5.1.4 で開いた（ユーザーが作品をすべて閉じた後に実施）。どれも開いた後、保存せずに閉じた。

| ファイル | 登録（`LockType`・`LockSpecified`・代わり） | 値 | CSP 5.1.4 |
|---|---|---|---|
| unk_unreg | 登録しない | 1 | 警告なしで開き、編集できる |
| unk_null | 4・2・なし | NULL | 警告なしで開き、編集できる |
| unk_plain | 0・0・なし | 1 | 警告なしで開き、編集できる |
| unk_row | 1・0・なし | 1 | 「このバージョンでは使用できないデータが含まれているレイヤーがあるため、一部のレイヤーが編集できません。」。そのレイヤーだけ鍵が付き、名前が赤くなる |
| unk_alt | 4・2・1・0 | 1 | unk_row と同じ（そのレイヤーだけロック） |
| unk_set | 4・2・なし | 1 | 「このバージョンでは使用できないデータがキャンバスに含まれているため、キャンバスを編集できません。」と、編集できるようにする操作の案内（作成した環境でバージョン互換情報を保存する設定にして別名で保存する、DEBUT なら PRO・EX を使う）。すべてのレイヤーに鍵が付き、タブは「（読み取り専用）」 |

分かったこと:

- CSP は、登録されていて、自分が知らず、値が入っている（NULL でも 0 でもない）列があると、その列の `LockType` に従ってロックする。登録されていない列と、`LockType` 0 の列は無視する
- `LockType` 1 はその行のレイヤー、`LockType` 4・`LockSpecified` 2 はキャンバス全体をロックする
- `AlternativeLockType`・`AlternativeLockSpecified` があれば、CSP 5.1.4 はそちらを使う（4・2 が 1・0 になり、レイヤーだけのロックになった）。
  `Has1_0_8` 以降の目印は代わりが 1・0 なので、2.0 以降の CSP では、新しい形式のデータを持つレイヤーだけがロックされると推測する。
  `Has1_0_6`・`Has1_0_7` と代わりのない `LockType` 4 の列は、キャンバス全体をロックする
- CSP は異常終了しなかった

## 5. グレードと古い版（未実施）

PC の CSP は EX だけで、PRO・DEBUT のライセンスと古い版の CSP はない。確認するには次のどれかが要る。

- PRO / DEBUT: 体験版（グレードを切り替えられる）か、そのライセンス
- 古い版: CELSYS の旧バージョンのページから入れた古い CSP（今の CSP と並べて入れられるかは未確認）

ファイルにグレードの記録はないので、グレードの違いは CSP が開くときの扱い（09 章の文言）だけと推測する。
2026-10-25 のユーザー判断で、PRO・DEBUT・古い版は同じ形式として扱い、この確認は未確認事項として保留した。
