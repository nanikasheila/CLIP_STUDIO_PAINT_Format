# V6c アニメーションの CSP での確認

アニメーションの形式（R17、[仕様 08 章](../spec/08-animation.md)）を、CSP EX で作った検査用のファイルと、
CSP の「アニメーション書き出し → 連番画像」との照合で確かめた。ユーザーのコーパスにはアニメーションのファイルがないため、
すべて CSP で作ったファイルを使った（作品ファイルは使っていない）。

## 実施条件

| 項目 | 値 |
|---|---|
| 実施日 | 2026-10-25 |
| CSP | CLIP STUDIO PAINT EX（Windows）。ユーザーの PC で Computer use により操作 |
| キャンバス | 新規アニメーション 390×270 px（仕上がり 320×240、基本枠 300×200）、セルは 1〜3 の黒い四角 |
| 書き出し | 連番画像、PNG、描画範囲「基準フレーム」（300×200）、2D カメラを適用あり・なし |
| 比較 | `cspf frames FILE DIR --timeline 1 [--camera no]` の出力と、RGBA の差の最大（255 段階） |
| ファイル | `C:\Users\SHEILA\cspcheck\cspformat\made\anim\`（下の表） |

## 作ったファイル

1 つ前のファイルに 1 つの操作を加えて保存し、差分（表・列・ミキサーの木）を比べて意味を決めた。

| ファイル | 操作 | 分かったこと |
|---|---|---|
| anim_00_new | 新規アニメーション（24 fps、36 フレーム） | `AnimationCutBank`・`TimeLine`・`Track`（用紙 2003、フォルダー 2000）ができる。ミキサー 2 つが同じ内容 |
| anim_01_cels | セルを 3 枚描き、フレームに指定 | `ImageCelName` の曲線（定数、`Tag` = セル名）、`TrackValueMap` |
| anim_02_range | 再生範囲 3〜29 | `StartFrame` 2・`EndFrame` 29（0 始まり、終わりは次） |
| anim_03_fps12 | 12 fps | `FrameRate`、`TimeClip.End` 90 → 180（キーは動かない） |
| anim_04_onion / 05_onion_on | オニオンスキンの設定・有効 | `Canvas.OnionSkin*` |
| anim_06_lighttable | セルをライトテーブルに登録 | `LayerType` 10016 の参照レイヤー、ルートの `LightTableInfo` |
| anim_07_keyframes / 08_transform | レイヤーのキーフレーム（不透明度、位置・拡大・回転） | 2001 の曲線、`TimeLineOriginalMipmap`、`LayerRenderMipmap` は保存されない |
| anim_09_camera | 2D カメラフォルダー | 2005 の曲線、`LayerType` 512。このときフォルダーは空だった |
| anim_10_timeline2 | 2 本目のタイムライン（30 fps）、ラベル 3 種 | `NextTimeLine`、タイムラインごとのトラック、`TimeLineLabel` の種類 |
| anim_11_linear_cam | e1 を開き、キーを等速補間にし、レイヤーをカメラフォルダーに入れる | `Interp` `Linear`、カメラの写し方 |
| anim_e1_edit | **このライブラリで** anim_10 のタイムライン 1 を 24 fps・範囲 1〜24・セル 1:3, 5:1, 9:2, 13:3, 20:1 に変えたもの（`cspf anim-set`） | CSP EX で開け、タイムラインに書いた通りに並ぶ |

## 1. ミキサーと値マップの読み書き（R17.1）

`crates/csp-lab/examples/anim_check.rs` で、全ファイルのミキサーを「展開 → 解析 → 直列化 → 圧縮」し、元と比べた。

| 対象 | 数 | バイト一致 |
|---|---|---|
| ミキサーの文書（0100・0110） | 80 | 80 |
| 圧縮した外部チャンク | 80 | 80 |
| `TrackValueMap` | 40 | 40 |

Python の `csp_format.animation` でも、80 個の文書が「解析 → 直列化」で元とバイト一致した。

## 2. フレームの描画（R17.3・R17.4）

| ファイル | タイムライン | フレーム | カメラ | 最大差 | 確かめたこと |
|---|---|---|---|---|---|
| anim_10_timeline2 | 1（12 fps、3〜29） | 27 | あり（空） | 2 | セルの切り替え、時間の写像、定数・滑らか補間、位置・拡大・回転・不透明度 |
| anim_11_linear_cam | 1（24 fps、1〜24） | 24 | あり | 3 | カメラ（位置・中心・回転 −15°・拡大 80%）と、カメラの中のキーフレームのレイヤー |
| anim_11_linear_cam | 1 | 24 | なし | 1 | 等速補間 |
| anim_e1_edit | 1（24 fps、1〜24） | 24 | なし | 1 | このライブラリの編集を CSP が読んだ結果 = このライブラリの描画 |

途中で分かって直したこと:

- 不透明度の差が最大 16 あった → 補間 `Default` は直線ではなく滑らか（smoothstep）。直して差 1
- e1 の最初の 2 フレームでキーフレームのレイヤーが CSP では消えていた → クリップ（`TimeClip`）の前では表示しない
- カメラの中のレイヤーの縁で差が最大 32 → 合成した画像をカメラで写すと 2 回標本化になる。レイヤーごとに変形を合わせて 1 回にして差 3

## 3. Python リーダー（R17.7）

12 件の各タイムラインの全フレーム（再生範囲の終わり + 1 まで、計 429）で、`read_animation(clip).frame_state(...)` の
非表示レイヤー・セル・変形（6 係数、差 1e-9 未満）・不透明度・カメラを Rust の `Animation::frame_state` と比べ、すべて一致した。
基準フレームと今のタイムラインも一致。

## 4. CSP が保存するプレビュー

アニメーションのファイルの `CanvasPreview` は、オニオンスキンの色付きの前後のセルを含んだり（anim_05）、
変形前の位置のレイヤーを描いたり（anim_10）、セルを描かなかったり（anim_06）する。
画面の表示状態に左右されるため、アニメーションの描画の照合には使わず、連番の書き出しを正とした。

## 5. 残り

- 傾きが 0 でない滑らか補間（グラフ編集）、クリップの終わりの後の表示、クリップの分割、音声レイヤー、フォルダーのセル、空のセル
- `LightTableInfo`・`Camera2DResizableImageInfo` の中身（描画には使わない）
- 新しいトラック・タイムラインを作る編集（今は既存のトラックの変更だけ）
