# V6 CSP で作ったファイルと CSP での確認

既存の作品ファイル（V1 のコーパス）は CSP の機能と設定をすべて使っているわけではない。
そこで、確かめたい機能だけを使ったファイルを CLIP STUDIO PAINT EX で作り、次の 2 点を調べた。

- 作品ファイルからは決められない値の意味（合成モードの番号など）
- このライブラリが書き出したファイルを CSP が正しく読むか（R12）

ここで扱うファイルは、どれも新しく作った検査用のファイルだけ。作品ファイルは使っていない。
ファイルはユーザーの PC の作業フォルダー（同期フォルダーの外）に置き、リポジトリには入れない（`.gitignore` で `*.clip` を除外）。

## 2. 書き出したファイルを CSP で開く（R12）

### 2.1 見つかった問題と原因

画素を書き換えたファイル（`blend_test.clip`）を CSP で開くと、書き換えたすべてのレイヤーで
「レイヤー画像またはレイヤーマスクが破損していたため、画像の一部を読み込めませんでした」と表示された。
自己整合性検査（V4）は通っていたので、CSP が何を拒んだかを次の変種で切り分けた（元は CSP で作った `blend_modes.clip`、書き換えるのは一番下のレイヤーだけ）。

| 変種 | 内容 | CSP |
|---|---|---|
| C | レイヤー名だけ変更（DB だけの変更） | 正常 |
| A | 100% のレベルだけ再符号化、外部チャンク ID は元のまま | 正常 |
| B | 全レベルを再符号化、外部チャンクを新しい ID で追加・元を削除 | **破損と表示** |
| B2 | B と同じ、ただし `ExternalChunk.ExternalID` を TEXT で記録 | 正常 |
| D | B2 と同じ、ただしファイル ID も新しくする | 正常、開いた直後から正しい表示 |

**原因 1: `ExternalChunk.ExternalID` の型。** 列は `BLOB` と宣言されているが、CSP は値を TEXT で入れ、TEXT として照合する。
ライブラリは新しい ID を BLOB で入れていたため、CSP から外部チャンクが見つからず、破損と判断された（SQLite では TEXT と BLOB は等しくならない）。
なお `Offscreen.BlockData` など、ID を参照する側の列は CSP も BLOB で入れている。

- 修正: 新しい ID を TEXT で入れる（`clip.rs` の `update_external_index`）。単体テスト `new_external_ids_are_indexed_as_text`
- 自己検査: `ContainerReport.external_ids_text`（全行が TEXT であること）を `ok()` の条件に加えた。修正前の変種 B はこの検査で不合格になる
- コーパスでの裏付け: V1 の 719 件で `ExternalChunk.ExternalID` 63,448 行がすべて TEXT、`Offscreen.BlockData` 286,168 行がすべて BLOB（`tools/corpus` と同じ方法で数えた。BLOB の ID を持つファイル 0 件）

**原因 2: ファイル ID（`Head` チャンクの 16 バイト）。** B2 は破損表示こそ出ないが、開いた直後のキャンバスに元のファイルの絵（変更前）が出て、
レイヤーの表示を切り替えるなどして再描画すると正しい絵になった。CSP は「別名で保存」のたびにファイル ID を新しくする。
元ファイル（同じ ID）を開いたままにしていたため、CSP が同じ文書とみなして描画のキャッシュを使ったと考えられる。ID を新しくした変種 D では、開いた直後から正しく表示された。

- 対応: `ClipFile::set_file_id` / `renew_file_id` を追加。編集して別ファイルとして書き出すときは `renew_file_id` を呼ぶ（`blend_test` 例で使用）

CSP が保存し直したファイルと比べて分かったこと（参考）:

- ルートとフォルダーの描画ミップマップは `Offscreen.Attribute` の `BlockSize` だけが更新され、外部チャンクは保存されない。CSP は開くときに合成し直す
- CSP 自身の保存では、ラスターレイヤーの下位ミップマップ（50%・25%・12.5%）にチャンクが保存されないことがある。参照先のチャンクがないのは正常（V1 の `not_stored`）
- `LayerThumbnail.Thumbnail…NeedRefresh` は真偽値ではなく、編集のたびに増える番号（コーパスで 100 万を超える値もある）
- 変更のない文書を「別名で保存」すると、CSP はファイル ID だけを変えて中身をそのまま書く

### 実測で決めた規則

最初の実装（W3C Compositing の式）では、次の 4 種が合わなかった（最大差 62〜255）。CSP の出力に合わせて直した。

| モード | CSP の規則 | 根拠 |
|---|---|---|
| 覆い焼き(発光)・加算(発光) | 不透明度で混ぜるのではなく、ソースの色に不透明度を掛けてから合成する（`dodge(b, s·α)`、`b + s·α`）。背景がない部分は通常と同じ | 不透明度 128 の部分: 修正前の最大差 102 / 62 → 2 / 0 |
| ハードミックス | 8 ビット値で `b + s > 255` なら 255。ちょうど 255 のときは `s < 128` なら 255 | ちょうど 255 になる画素 74 個をすべて説明できる |
| カラー比較(暗)・(明) | 輝度 `0.3R + 0.59G + 0.11B` を 8 ビットに丸めて比べ、同じならソースを選ぶ | 7,938 画素で選択の食い違い 0（丸めない比較では 6〜20 個食い違う） |

### 残っている差

色相・彩度・カラー・輝度の 4 モードは最大 3〜7 の差が残る。差はすべて、合成後の色が 0〜1 をはみ出して戻す処理（ClipColor）の画素で出る。
CSP は戻すときの基準の輝度が W3C の式より 0〜4 ほど高く、内部の整数計算の違いとみられる。平均差は 0.5 未満なので、今は記録だけにとどめる。

## 4. レイヤー効果「フチ」（境界効果）

### 作り方

1. `effect_test base` で、28 枚のラスターレイヤーを通常モードにし、各セルに縁の形が違う図形
   （硬い円、アンチエイリアスの円、1 px の線、1 画素、透明度のグラデーション、四角）を置いたファイルを作る
2. CSP で 1 枚のレイヤーに「境界効果 → フチ」を設定して保存する。CSP は効果を初めて使うときに
   `Layer` に効果の列（`LayerEffectInfo` ほか）を追加するので、これがひな形になる
3. `effect_test vary` で、ひな形の `LayerEffectInfo` を他の 27 枚に写し、フチの太さ（0.5〜20）と色を変える。
   各設定を `LayerEffectEdgeNewRender` = 1（今の CSP が付ける値）と なし（コーパスのほとんど）の両方で作る
4. CSP で開き、「画像を統合して書き出し → .png」で書き出して比べる

### `LayerEffectInfo` の形式

ビッグエンディアン。全体の大きさ（`u32`）、版（`u32`、2）、そのあと名前付きの区画が並ぶ。
名前は UTF-16BE の文字数（`u32`）と文字。`EffectEdge`（24 バイト）と `EffectTone`（76 バイト）は大きさの欄がなく固定長、
それ以降の区画（`EffectTextureMap`、`EffectApplyOpacity`、`EffectToneAreaColor`、`EffectTonePosterize`、`EffectWaterEdge`、`EffectLine`）は先頭に自分を含む大きさ（`u32`）を持つ。
新しい CSP は `EffectLine` の記載の大きさ（116）の後ろに 20 バイトを足して保存する（記載は 116 のまま）。次の区画名までを同じ区画として扱うと、往復でバイト一致する。

| 区画 | 内容（分かった範囲） |
|---|---|
| `EffectEdge` | 有効（`u32`）、太さ（`f64`、キャンバスの画素）、色（`u32` × 3、上位 8 ビットが値） |
| `EffectApplyOpacity` | 大きさ、描画の透明度を反映（`u32`） |
| `EffectTone` | 有効（`u32`）、解像度らしき値（`f64`、300 / 350 / 600）、線数（`f64`、60）、角度（45）ほか |

効果は `LayerEffectAttached` = 1 のときだけ有効で、無効なレイヤーにも設定は残る。
コーパス（719 件）では、有効な効果はフチ 1,531 レイヤー、トーン 約 210 レイヤー、抽出線 6、水彩境界 3。

### フチの規則（実測）

- フチの不透明度: 画素の中心どうしの距離 d について、`max over q of a(q) × clamp(太さ + 1.5 − d, 0, 1)`。
  つまり「太さ + 0.5」までは完全に塗り、その先 1 px で 0 になる
- レイヤー自身はフチの上に描かれ、フチは不透明度をその値まで補うだけ（結果の不透明度 = `max(a, フチ)`）。半透明の画素の下でフチの色が濃く出ることはない
- `LayerEffectEdgeNewRender` の有無で、100% 表示の書き出しは変わらなかった

結果: 28 レイヤー（太さ 0.5・1・1.5・2・2.5・3・4.13・5・7・10・20、黒・白・赤・青・黄、2 つのレンダラー）で、
**画像全体の最大差 2/255、平均 0.025**（`effect.rs` の `draw_border`、単体テストあり）。

「描画の透明度を反映」をオフにした場合（透明度を 0/1 に二値化すると仮定）と、トーン・水彩境界・抽出線はまだ確かめていない。

## 5. 新規作成・レイヤーの追加と削除・属性の変更（R12・R13）

CLI（`cspf new`・`add-layer`・`add-folder`・`set`・`remove-layer`）でファイルを作り、CSP で開いてレイヤーパレットを確かめ、
「画像を統合して書き出し → .png」と、このライブラリの描画を `render_compare` で比べた（2026-10-24〜25）。
画像は合成した模様だけ（作品の画素は使っていない）。

### 5.1 新規作成と、既存ファイルへの追加・削除

| ファイル | 作り方 | CSP のレイヤーパレット | 書き出しとの差 |
|---|---|---|---|
| `new_512` | `new --size 512x512 --dpi 600 --image 模様` | 用紙＋「レイヤー 1」、512×512・600 dpi | 0（全画素一致） |
| `new_wide` | `new --size 1500x700 --paper d4e8ff --image 模様` | 用紙（水色）＋「レイヤー 1」 | 0 |
| `new_nopaper` | `new --size 300x300 --paper none --image 模様` | 「レイヤー 1」だけ（背景は透明） | 0（透明部分を含む） |
| `bm_added` | CSP で作った `blend_modes.clip` に `add-layer`（100, 50 に模様） | 一番上に「追加レイヤー」 | 0 |
| `bm_removed` | `blend_modes.clip` から `remove-layer 5` | 該当レイヤーだけがない | 0 |

警告や破損の表示はなかった。透明な画素は、CSP の書き出しが RGB に白を入れるため、比較は白の上に合成した色と不透明度で行う（`render_compare`）。

**CSP で保存し直したファイルとの構造の差（R13）。** `attr.clip`（下の 5.2）を CSP で開き、新しいラスターレイヤーを 1 枚足して「別名で保存」した（`attr_cspsaved.clip`）。

- テーブルと列の構成は同じ。このライブラリが書いたレイヤーの行は、CSP が保存し直しても全列そのまま残った
- CSP が足したレイヤーとこのライブラリが足したレイヤーの違いは、ID・名前・UUID・選択状態と `LightTableInfo`（CSP は NULL、ライブラリはコーパスで見た 15 バイト）だけ
- CSP は `MainId` 11 を使い、`ElemScheme.MaxIndex` を 9 から 11 にした（10 は欠番）。ID は連番でなくてよい
- `ExternalChunk` は 28 → 17 行。CSP は下位のミップマップのチャンクを保存しない（V1 の `not_stored` と同じ）。ライブラリは全レベルを保存する

### 5.2 属性の変更とフォルダー、クリッピング

`attr.clip`: 512×512 の新規ファイルに、半透明の市松模様を持つ「乗算 50%」、その上にクリッピングした「スクリーン」、非表示のレイヤー、
不透明度 70% のフォルダー（中に「オーバーレイ」）を足したもの。`attr_rm.clip` はそこからフォルダーを消したもの。

- CSP のレイヤーパレットは、不透明度・合成モード・非表示・クリッピング（赤い線）・フォルダーの中身とも、設定どおりに表示された
- 最初の比較で、クリッピングした範囲だけ最大 49/255 の差が出た。原因はクリッピングの合成の規則（次の 5.3）。直したあとは最大差 2/255（PSNR 57 dB）

### 5.3 クリッピングの規則（`clip.clip`、900×900）

4 つの区画で、下地（半透明の画素を持つレイヤー）とクリッピングの組み合わせを変えて比べた。

| 区画 | 下地 | クリッピングしたもの | 旧規則 | 新規則 |
|---|---|---|---|---|
| A | 通常 100% | 通常のラスター | 49 | 0 |
| B | 通常 100% | 「乗算」のフォルダー（中にラスター） | 43 | 1 |
| C | 通常 50% | 通常のラスター 60% | 30 | 1 |
| D | 通常 100% | 「加算（発光）」のラスター | 0 | 0 |
| （5.2） | 乗算 50% | スクリーンのラスター | 49 | 2 |

（数字は書き出しとの最大差 /255。）

- 旧規則: クリッピングしたレイヤーを、下の合成結果に直接重ね、下地の不透明度で覆う
- **新規則（CSP と一致）: 下地とその上のクリッピングしたレイヤーを 1 つのまとまりとして、まず下地だけの上にクリッピングしたレイヤーを重ねる（下地の不透明度は変えない）。そのまとまりを、下地の合成モード・不透明度・マスクで下に重ねる**
- 下地が「通過」のフォルダーや色調補正レイヤー（自分の画素を持たない）のときは、旧規則のまま（未確認）
- フチ（境界効果）付きの下地では、フチを含めた下地の上にクリッピングしたレイヤーが重なる（`clip_edge.clip`、太さ 81 px で差 1 以内）

### 5.4 コーパスの診断で見つかった規則（構造だけを見て決め、次の V3 で確かめる）

描画と保存されたプレビューの差が大きい作品を、レイヤーを 1 枚ずつ外して調べた（`examples/diagnose.rs`、名前や画素は出さない）。

- **移動したレイヤーのマスク**: マスクの位置（`LayerMaskOffset` ＋ `LayerMaskRenderOffset`）はレイヤーのオフセットからの相対。
  オフセット (7018, 1)・マスクのオフセット (−7018, −1) で、キャンバスと同じ大きさのマスクが (0, 0) に来る。見開きの作品で 5.9 → 53.3 dB
- **移動したグラデーション**: `GradationFillInfo` の始点・終点もレイヤーのオフセットからの相対（ベクターの点と同じ）。15.7 → 26.6 dB
- **画素を持つグラデーションレイヤー**: 画素が保存されていても、設定から描く（画素は古いことがある）。10.1 → 38.9 dB
- **プレビューの大きさ**: プレビューはキャンバスを半分にして切り捨てた大きさなので、倍率はレベルの倍率よりわずかに小さい（826 / 1653）。
  差が 0.5% 以内なら、レベルの画素をそのまま使う（1 画素未満の再標本化で線がぼける）。29.0 → 22.5 dB に落ちていたのが戻った
