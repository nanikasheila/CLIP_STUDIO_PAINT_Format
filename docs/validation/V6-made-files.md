# V6 CSP で作ったファイルと CSP での確認

既存の作品ファイル（V1 のコーパス）は CSP の機能と設定をすべて使っているわけではない。
そこで、確かめたい機能だけを使ったファイルを CLIP STUDIO PAINT EX で作り、次の 2 点を調べた。

- 作品ファイルからは決められない値の意味（合成モードの番号など）
- このライブラリが書き出したファイルを CSP が正しく読むか（R12）

ここで扱うファイルは、どれも新しく作った検査用のファイルだけ。作品ファイルは使っていない。
ファイルはユーザーの PC の作業フォルダー（同期フォルダーの外）に置き、リポジトリには入れない（`.gitignore` で `*.clip` を除外）。

## 2. 書き出したファイルを CSP で開く（R12）

### 2.1 見つかった問題と原因

画素を書き換えたファイル（`blend_test.clip`）を CSP で開くと、書き換えたすべてのレイヤーで
「レイヤー画像またはレイヤーマスクが破損していたため、画像の一部を読み込めませんでした」と表示された。
自己整合性検査（V4）は通っていたので、CSP が何を拒んだかを次の変種で切り分けた（元は CSP で作った `blend_modes.clip`、書き換えるのは一番下のレイヤーだけ）。

| 変種 | 内容 | CSP |
|---|---|---|
| C | レイヤー名だけ変更（DB だけの変更） | 正常 |
| A | 100% のレベルだけ再符号化、外部チャンク ID は元のまま | 正常 |
| B | 全レベルを再符号化、外部チャンクを新しい ID で追加・元を削除 | **破損と表示** |
| B2 | B と同じ、ただし `ExternalChunk.ExternalID` を TEXT で記録 | 正常 |
| D | B2 と同じ、ただしファイル ID も新しくする | 正常、開いた直後から正しい表示 |

**原因 1: `ExternalChunk.ExternalID` の型。** 列は `BLOB` と宣言されているが、CSP は値を TEXT で入れ、TEXT として照合する。
ライブラリは新しい ID を BLOB で入れていたため、CSP から外部チャンクが見つからず、破損と判断された（SQLite では TEXT と BLOB は等しくならない）。
なお `Offscreen.BlockData` など、ID を参照する側の列は CSP も BLOB で入れている。

- 修正: 新しい ID を TEXT で入れる（`clip.rs` の `update_external_index`）。単体テスト `new_external_ids_are_indexed_as_text`
- 自己検査: `ContainerReport.external_ids_text`（全行が TEXT であること）を `ok()` の条件に加えた。修正前の変種 B はこの検査で不合格になる
- コーパスでの裏付け: V1 の 719 件で `ExternalChunk.ExternalID` 63,448 行がすべて TEXT、`Offscreen.BlockData` 286,168 行がすべて BLOB（`tools/corpus` と同じ方法で数えた。BLOB の ID を持つファイル 0 件）

**原因 2: ファイル ID（`Head` チャンクの 16 バイト）。** B2 は破損表示こそ出ないが、開いた直後のキャンバスに元のファイルの絵（変更前）が出て、
レイヤーの表示を切り替えるなどして再描画すると正しい絵になった。CSP は「別名で保存」のたびにファイル ID を新しくする。
元ファイル（同じ ID）を開いたままにしていたため、CSP が同じ文書とみなして描画のキャッシュを使ったと考えられる。ID を新しくした変種 D では、開いた直後から正しく表示された。

- 対応: `ClipFile::set_file_id` / `renew_file_id` を追加。編集して別ファイルとして書き出すときは `renew_file_id` を呼ぶ（`blend_test` 例で使用）

CSP が保存し直したファイルと比べて分かったこと（参考）:

- ルートとフォルダーの描画ミップマップは `Offscreen.Attribute` の `BlockSize` だけが更新され、外部チャンクは保存されない。CSP は開くときに合成し直す
- CSP 自身の保存では、ラスターレイヤーの下位ミップマップ（50%・25%・12.5%）にチャンクが保存されないことがある。参照先のチャンクがないのは正常（V1 の `not_stored`）
- `LayerThumbnail.Thumbnail…NeedRefresh` は真偽値ではなく、編集のたびに増える番号（コーパスで 100 万を超える値もある）
- 変更のない文書を「別名で保存」すると、CSP はファイル ID だけを変えて中身をそのまま書く

### 実測で決めた規則

最初の実装（W3C Compositing の式）では、次の 4 種が合わなかった（最大差 62〜255）。CSP の出力に合わせて直した。

| モード | CSP の規則 | 根拠 |
|---|---|---|
| 覆い焼き(発光)・加算(発光) | 不透明度で混ぜるのではなく、ソースの色に不透明度を掛けてから合成する（`dodge(b, s·α)`、`b + s·α`）。背景がない部分は通常と同じ | 不透明度 128 の部分: 修正前の最大差 102 / 62 → 2 / 0 |
| ハードミックス | 8 ビット値で `b + s > 255` なら 255。ちょうど 255 のときは `s < 128` なら 255 | ちょうど 255 になる画素 74 個をすべて説明できる |
| カラー比較(暗)・(明) | 輝度 `0.3R + 0.59G + 0.11B` を 8 ビットに丸めて比べ、同じならソースを選ぶ | 7,938 画素で選択の食い違い 0（丸めない比較では 6〜20 個食い違う） |

### 残っている差

色相・彩度・カラー・輝度の 4 モードは最大 3〜7 の差が残る。差はすべて、合成後の色が 0〜1 をはみ出して戻す処理（ClipColor）の画素で出る。
CSP は戻すときの基準の輝度が W3C の式より 0〜4 ほど高く、内部の整数計算の違いとみられる。平均差は 0.5 未満なので、今は記録だけにとどめる。

## 4. レイヤー効果「フチ」（境界効果）

### 作り方

1. `effect_test base` で、28 枚のラスターレイヤーを通常モードにし、各セルに縁の形が違う図形
   （硬い円、アンチエイリアスの円、1 px の線、1 画素、透明度のグラデーション、四角）を置いたファイルを作る
2. CSP で 1 枚のレイヤーに「境界効果 → フチ」を設定して保存する。CSP は効果を初めて使うときに
   `Layer` に効果の列（`LayerEffectInfo` ほか）を追加するので、これがひな形になる
3. `effect_test vary` で、ひな形の `LayerEffectInfo` を他の 27 枚に写し、フチの太さ（0.5〜20）と色を変える。
   各設定を `LayerEffectEdgeNewRender` = 1（今の CSP が付ける値）と なし（コーパスのほとんど）の両方で作る
4. CSP で開き、「画像を統合して書き出し → .png」で書き出して比べる

### `LayerEffectInfo` の形式

ビッグエンディアン。全体の大きさ（`u32`）、版（`u32`、2）、そのあと名前付きの区画が並ぶ。
名前は UTF-16BE の文字数（`u32`）と文字。`EffectEdge`（24 バイト）と `EffectTone`（76 バイト）は大きさの欄がなく固定長、
それ以降の区画（`EffectTextureMap`、`EffectApplyOpacity`、`EffectToneAreaColor`、`EffectTonePosterize`、`EffectWaterEdge`、`EffectLine`）は先頭に自分を含む大きさ（`u32`）を持つ。
新しい CSP は `EffectLine` の記載の大きさ（116）の後ろに 20 バイトを足して保存する（記載は 116 のまま）。次の区画名までを同じ区画として扱うと、往復でバイト一致する。

| 区画 | 内容（分かった範囲） |
|---|---|
| `EffectEdge` | 有効（`u32`）、太さ（`f64`、キャンバスの画素）、色（`u32` × 3、上位 8 ビットが値） |
| `EffectApplyOpacity` | 大きさ、描画の透明度を反映（`u32`） |
| `EffectTone` | 有効、解像度、網点の形、濃度の取り方、線数、角度ほか（6 章） |

効果は `LayerEffectAttached` = 1 のときだけ有効で、無効なレイヤーにも設定は残る。
コーパス（719 件）では、有効な効果はフチ 1,531 レイヤー、トーン 約 210 レイヤー、抽出線 6、水彩境界 3。

### フチの規則（実測）

- フチの不透明度: 画素の中心どうしの距離 d について、`max over q of a(q) × clamp(太さ + 1.5 − d, 0, 1)`。
  つまり「太さ + 0.5」までは完全に塗り、その先 1 px で 0 になる
- レイヤー自身はフチの上に描かれ、フチは不透明度をその値まで補うだけ（結果の不透明度 = `max(a, フチ)`）。半透明の画素の下でフチの色が濃く出ることはない
- `LayerEffectEdgeNewRender` の有無で、100% 表示の書き出しは変わらなかった

結果: 28 レイヤー（太さ 0.5・1・1.5・2・2.5・3・4.13・5・7・10・20、黒・白・赤・青・黄、2 つのレンダラー）で、
**画像全体の最大差 2/255、平均 0.025**（`effect.rs` の `draw_border`、単体テストあり）。

「描画の透明度を反映」をオフにした場合（透明度を 0/1 に二値化すると仮定）と、水彩境界・抽出線はまだ確かめていない（トーンは 6 章）。

## 5. 新規作成・レイヤーの追加と削除・属性の変更（R12・R13）

CLI（`cspf new`・`add-layer`・`add-folder`・`set`・`remove-layer`）でファイルを作り、CSP で開いてレイヤーパレットを確かめ、
「画像を統合して書き出し → .png」と、このライブラリの描画を `render_compare` で比べた（2026-10-24〜25）。
画像は合成した模様だけ（作品の画素は使っていない）。

### 5.1 新規作成と、既存ファイルへの追加・削除

| ファイル | 作り方 | CSP のレイヤーパレット | 書き出しとの差 |
|---|---|---|---|
| `new_512` | `new --size 512x512 --dpi 600 --image 模様` | 用紙＋「レイヤー 1」、512×512・600 dpi | 0（全画素一致） |
| `new_wide` | `new --size 1500x700 --paper d4e8ff --image 模様` | 用紙（水色）＋「レイヤー 1」 | 0 |
| `new_nopaper` | `new --size 300x300 --paper none --image 模様` | 「レイヤー 1」だけ（背景は透明） | 0（透明部分を含む） |
| `bm_added` | CSP で作った `blend_modes.clip` に `add-layer`（100, 50 に模様） | 一番上に「追加レイヤー」 | 0 |
| `bm_removed` | `blend_modes.clip` から `remove-layer 5` | 該当レイヤーだけがない | 0 |

警告や破損の表示はなかった。透明な画素は、CSP の書き出しが RGB に白を入れるため、比較は白の上に合成した色と不透明度で行う（`render_compare`）。

**CSP で保存し直したファイルとの構造の差（R13）。** `attr.clip`（下の 5.2）を CSP で開き、新しいラスターレイヤーを 1 枚足して「別名で保存」した（`attr_cspsaved.clip`）。

- テーブルと列の構成は同じ。このライブラリが書いたレイヤーの行は、CSP が保存し直しても全列そのまま残った
- CSP が足したレイヤーとこのライブラリが足したレイヤーの違いは、ID・名前・UUID・選択状態と `LightTableInfo`（CSP は NULL、ライブラリはコーパスで見た 15 バイト）だけ
- CSP は `MainId` 11 を使い、`ElemScheme.MaxIndex` を 9 から 11 にした（10 は欠番）。ID は連番でなくてよい
- `ExternalChunk` は 28 → 17 行。CSP は下位のミップマップのチャンクを保存しない（V1 の `not_stored` と同じ）。ライブラリは全レベルを保存する

### 5.2 属性の変更とフォルダー、クリッピング

`attr.clip`: 512×512 の新規ファイルに、半透明の市松模様を持つ「乗算 50%」、その上にクリッピングした「スクリーン」、非表示のレイヤー、
不透明度 70% のフォルダー（中に「オーバーレイ」）を足したもの。`attr_rm.clip` はそこからフォルダーを消したもの。

- CSP のレイヤーパレットは、不透明度・合成モード・非表示・クリッピング（赤い線）・フォルダーの中身とも、設定どおりに表示された
- 最初の比較で、クリッピングした範囲だけ最大 49/255 の差が出た。原因はクリッピングの合成の規則（次の 5.3）。直したあとは最大差 2/255（PSNR 57 dB）

### 5.3 クリッピングの規則（`clip.clip`、900×900）

4 つの区画で、下地（半透明の画素を持つレイヤー）とクリッピングの組み合わせを変えて比べた。

| 区画 | 下地 | クリッピングしたもの | 旧規則 | 新規則 |
|---|---|---|---|---|
| A | 通常 100% | 通常のラスター | 49 | 0 |
| B | 通常 100% | 「乗算」のフォルダー（中にラスター） | 43 | 1 |
| C | 通常 50% | 通常のラスター 60% | 30 | 1 |
| D | 通常 100% | 「加算（発光）」のラスター | 0 | 0 |
| （5.2） | 乗算 50% | スクリーンのラスター | 49 | 2 |

（数字は書き出しとの最大差 /255。）

- 旧規則: クリッピングしたレイヤーを、下の合成結果に直接重ね、下地の不透明度で覆う
- **新規則（CSP と一致）: 下地とその上のクリッピングしたレイヤーを 1 つのまとまりとして、まず下地だけの上にクリッピングしたレイヤーを重ねる（下地の不透明度は変えない）。そのまとまりを、下地の合成モード・不透明度・マスクで下に重ねる**
- 下地が「通過」のフォルダーや色調補正レイヤー（自分の画素を持たない）のときは、旧規則のまま（未確認）
- フチ（境界効果）付きの下地では、フチを含めた下地の上にクリッピングしたレイヤーが重なる（`clip_edge.clip`、太さ 81 px で差 1 以内）

### 5.4 コーパスの診断で見つかった規則（構造だけを見て決め、次の V3 で確かめる）

描画と保存されたプレビューの差が大きい作品を、レイヤーを 1 枚ずつ外して調べた（`examples/diagnose.rs`、名前や画素は出さない）。

- **移動したレイヤーのマスク**: マスクの位置（`LayerMaskOffset` ＋ `LayerMaskRenderOffset`）はレイヤーのオフセットからの相対。
  オフセット (7018, 1)・マスクのオフセット (−7018, −1) で、キャンバスと同じ大きさのマスクが (0, 0) に来る。見開きの作品で 5.9 → 53.3 dB
- **移動したグラデーション**: `GradationFillInfo` の始点・終点もレイヤーのオフセットからの相対（ベクターの点と同じ）。15.7 → 26.6 dB
- **画素を持つグラデーションレイヤー**: 画素が保存されていても、設定から描く（画素は古いことがある）。10.1 → 38.9 dB
- **プレビューの大きさ**: プレビューはキャンバスを半分にして切り捨てた大きさなので、倍率はレベルの倍率よりわずかに小さい（826 / 1653）。
  差が 0.5% 以内なら、レベルの画素をそのまま使う（1 画素未満の再標本化で線がぼける）。29.0 → 22.5 dB に落ちていたのが戻った

## 6. レイヤー効果「トーン」（2026-10-25）

### 作り方

`examples/tone_test.rs` で、4 章のひな形（`effects_tmpl.clip`、512×512、600 dpi、用紙は灰色 212）の 8 枚のレイヤーを 2 列 × 4 段のセルに並べ、
それぞれにパターンを描いて `EffectTone` を有効にした。CSP で開き、「画像を統合して書き出し → .png」で書き出して画素を比べた。

- `tone_a.clip`: 上半分に不透明な灰色の横グラデーション、下半分に黒の透明度グラデーション。線数 10・20・30・60、角度 0、網点の形 2・4、固定濃度 51%
- `tone_b.clip`: 灰色 128 の透明度グラデーションと透明度 50% の灰色グラデーション、赤・緑・青・黄の単色（線数 60）、形 4 の角度 0、角度 30、
  語 13・14 = (5, 7)、固定濃度 20%・80%、語 11 = 100

### `EffectTone` の形式（76 バイト、ビッグエンディアン）

| 位置 | 型 | 中身 | 確度 |
|---|---|---|---|
| +0 | u32 | 有効（1） | 確認済み |
| +4 | f64 | 線数の基準の解像度。コーパスの 87 作品ではすべてキャンバスの解像度と同じ | 確認済み |
| +12 | u32 | 網点の形: 1 丸、2 四角、4 線（コーパスには 5・7・21 もある。未解明） | 1・2 確認済み、4 は 0° のみ |
| +16 | u32 | 濃度の取り方: 0 画像から、2 固定 | 確認済み |
| +20 | u32 | 固定濃度（%） | 確認済み |
| +24 | f64 | 線数（線/インチ） | 確認済み |
| +40 | u32 | 角度（度） | 確認済み |

### トーンの規則（実測）

- **格子**: キャンバスの原点が基準。格子の辺は、周期（解像度 ÷ 線数）を角度の向き（y は下向き）に取り、x・y をそれぞれ整数に丸める。
  30 px の 45° は (21, 21)、30° は (26, 15)。網点の中心はセルの中央で、セルの角が暗い所の穴の位置
- **しきい値**: 画素の左上の点で、セルの中の位置ごとのしきい値（その位置より先に塗られるセルの割合）と比べる。
  丸は半分まで円で育ち、その先は円い穴になる（PostScript の round の網点関数）。四角は四角で、線は 2 本目の辺の向きに太る
- **二値**: 結果は黒・白・透明のどれか。濃度を画像から取るとき、透明度がしきい値を超える所を描き、そのうち「暗さ × 透明度」がしきい値を超える所を黒、
  残りを白にする。暗さは `1 − (0.114 R + 0.299 G + 0.587 B)`（BT.601 の係数が別の順でチャンネルに掛かる。単色 4 つの網点の割合から決めた）
- **固定濃度**: 網点は円（半分を超えても穴にならない）で黒、レイヤーの画素がある所すべてに描き、残りは透明

結果（セルごとの画素の一致率、`tone.rs`）:

| 設定 | 一致率 |
|---|---|
| 丸、線数 10・20・30・60、角度 0・30・45 | 98.0〜99.5% |
| 四角 | 99.3% |
| 線、角度 0 | 98.3% |
| 固定濃度 20%・51%・80% | 98.3〜99.9% |
| 透明度との組み合わせ | 99.2% |
| 単色（赤・緑・青・黄） | 96.8% |
| 線、角度 45 | 82%（規則が違う。未解明） |
| 語 13・14 = (5, 7) | 62%（未解明） |

残る差は網点の縁の 1 画素。線の 45° と語 13・14 は、描画の報告で `tones_approximate` に数える。

## 7. ベクターの線の太さ（2026-10-25）

ベクターレイヤーは画素を保存しないことが多く、CSP は開くときに描き直す（05 章）。線の太さを決める規則を、筆圧と大きさがわかっている直線を並べたファイルで実測した。

### 作り方

CSP の G ペンで線を数本引いた `vec_tmpl.clip`（100 × 60 mm、350 dpi）をひな形にし、`examples/vec_test.rs` でベクターレイヤーのオブジェクトを差し替えた。
最初のオブジェクトを型にして、長さ・筆圧・大きさの決まった直線の格子を作り、ブラシの設定（`BrushStyle`）と筆圧の曲線（`BrushEffectorGraphData`）を書き換える。
CSP で開いて「画像を統合して書き出し → .png」で書き出し、格子のセルごとに線の中ほど 40 px のインク（透明度の和）を測って線の幅とした。

### 実測で決めた規則

- オブジェクトのブラシの大きさは半径。倍率 1 の線の幅は `2 × 大きさ`
- 筆圧の曲線は、先頭 `ControlNumber` 個の点を制御点とする 2 次 B スプライン。最後の点の x より先は `y × x / x_last`
  （i・j の初回は `ControlNumber` が 3 のまま 4・5 点を書き、先頭 3 点だけが使われることからわかった）。点が `ControlNumber` より少ないと CSP は開けない
- アンチエイリアス: 0 は画素の中心が半径の内側なら塗る（幅はちょうど `2R`）。1・2・3 は約 1 px の傾斜で、インクは `2R − 減り`。幅 2 px 未満の線は約 `R`。
  減り（px）は半径で変わる（a〜m の 3 列、半径 1〜20 の測定値をならしたもの）:

  | 半径 | 1 | 1.5 | 2 | 3 | 4 | 6 | 10 | 20 |
  |---|---|---|---|---|---|---|---|---|
  | 弱（1） | 1.05 | 1.25 | 1.13 | 1.05 | 0.91 | 0.91 | 0.82 | 0.65 |
  | 中（2） | 1.05 | 1.25 | 1.45 | 1.49 | 1.31 | 1.18 | 1.15 | 1.09 |
  | 強（3） | 1.05 | 1.25 | 1.45 | 1.71 | 1.68 | 1.47 | 1.44 | 1.42 |

- 大きさの影響のフラグ 0x40・0x80・0x100、点の値 1 は、筆圧一定の直線では効かない。点の値 10 は最初の点までの距離に近く、それより短い区間は描かれない。値 2 を 0 にすると描かれない（ヘッダー 92 の格子。ヘッダー 88 の線では描かれる）
- 先端は楕円。厚さが短軸と長軸の比で、線の幅は楕円の線に垂直な方向の幅
  （厚さ 0.4・半径 20: 水平の線 37.9 px、垂直の線 15.5 px、45° の線 29.3 px）
- 向き: `RotationEffector` のビット 0x01 がないと `RotationBase` は使われない（ta と tb は同じ画素）。0x01 があると短軸が `RotationBase` 度（y は下向き）を向く。
  0x40 は線の進行方向を足す（te はどの向きの線も 29 px）。0x80 は点ごとの乱数（`RotationRandom` の量、tf・tj は縁がぎざぎざで、幅は長軸の幅に近い）。
  0x02・0x10・0x20 は筆圧一定・傾きなしの線では効かない（tc・td・tg・th は同じ画素）
- 厚さの影響（`ThicknessEffector`）は大きさの影響と同じ形で、筆圧 0.5 で厚さ 0.5（ti）
- 楕円の先端では、アンチエイリアスで減るインクが「線に垂直な幅 ÷ 線に沿った幅」に比例して 0.4〜1.75 倍になる（水平の線 −2.1 px、垂直の線 −0.5 px）
- 点のつなぎ方: ヘッダー 92 の型（ひな形の G ペンの線）で作った s・u は、点の値 10 によらず点から点への直線。ヘッダー 88 の型（tq_s）では曲線になる。
  曲線の中心線にいちばん合うのは、点での接線 `0.7 × (次 − 前)`、端の接線 `0.55 × (隣 − 端)` の 3 次エルミート曲線（V 字・ジグザグ・四角で、インクの画素から曲線までの平均距離が線幅 8 px の一様な線と同じ約 2 px）。
  コーパスの角のある四角（コマ枠、点フラグ 0x3）は直線で保存画素と一致するので、点フラグ 0x2 を角とした
- 速度: 大きさの影響 0x41 の最小値 m で、点の値 2 が v の線の幅は `2R × (1 − (1 − m) × v)`（m = 0.6・0.2、v = 0〜1 の 12 本で ±0.01）。0x51 も同じ。
  移した実際の線（tq_c）で点の値 2 を 0 にすると、0x40 を外したのと同じ画素になる。ヘッダー 92 の線では効かない（a〜j の h）
- 0x81（乱数、最小値 0.2）は線の幅が点ごとに 31〜38 px（大きさ 20）で揺れ、平均は倍率 0.9。0x101 は効かない
- 乱数の種: 点の値 11 は点ごとの `u32` の種（`f32` として読むと意味のない値）。CSP で引いた線ではばらばらで、試験の線（0）では乱数が線全体で同じ値になる。
  種があってもブラシに乱数がなければ画素は変わらない（dr_s と dr_q が全画素一致）
- 乱数の倍率（移した実際の線で、乱数を外したファイルとのインクの比から）: 大きさは最小値 0.89 で 0.954、不透明度は最小値 0.51 で 0.796。
  `1 − (1 − 最小値) × u` とおくと、大きさ・厚さは u = 0.467 − 0.428 × (1 − 最小値)（0.1〜0.5 に収める）、不透明度は u = 0.42 で合う
- 向きの乱数（`RotationEffector` 0x80）: 種を入れた試験の線で、進行方向に横向きの先端（dr_r、乱数 0.3）はインク 0.97 倍（細るだけで太らない）。
  向き固定・乱数 1.0（dr_f）はどの向きの線も同じ太さで、横向きの先端の 0.92 倍。点ごとに ±`RotationRandom` × 180° 回した楕円の幅の平均から、最大の幅へ 0.3 寄せた丸い先端でよく合う
- 厚さの乱数は、試験の線で縁が波打ち、インクが大きさ 4 で 0.92 倍、大きさ 20 で 0.96 倍、移した線で 0.987 倍になる。線に沿った先端の長さだけが変わる向きでも細る。原因は未解明で、近似には入れない
- 点を打つ間隔: `AutoIntervalType` 1〜3（自動。コーパスの行の 95%）は画素を変えない（dr_i、rd_w が 0.99〜1.0 倍）。
  0（固定、`IntervalBase` が間隔）は、丸い先端で 0.1 にすると 0.988 倍、厚さ 0.51 の楕円で 0.2 にすると 0.841 倍（dr_j）。固定の間隔と楕円の先端の組はコーパスにほとんどないので近似には入れない
- 筆圧の曲線の点が 6 個のもの（作品から移した大きさの曲線と、横ばいのある厚さの曲線）も、上の B スプラインで CSP と合う（rc_1・rc_2 が 0.98・1.005）
- 細い楕円の先端ではアンチエイリアスの段階がほぼ効かない。厚さ 0.51 の進行方向の先端（dr_a*）で、1・3 は 2 の 1.01・0.992 倍（0 は 1.24 倍）。
  作品から移した線（tz_b、厚さが筆圧で 0.51 以下）でも、1 を 2 に変えた書き出しは全画素ほぼ一致（PSNR 66.8 dB）。
  一方、厚さの設定が 1.02 で筆圧によって細る先端（tx_a）は、弱（1）の減りで合う（中にすると 0.95）。
  そこで、厚さの設定（`ThicknessBase`）が 1 ならその段階の値、0.51 以下なら中（2）の値とし、その間を直線で結んだ（点ごとの厚さで切り替えると 0x11 の作品が 1.01 → 0.97 に細った）
- 厚さの曲線の終点の y が 1 でない試験ファイル（dr_b*、終点 (1, 0.51)）は、CSP では丸い先端とほぼ同じ（0.975 倍）になった。作品の曲線は終点が (1, 1) なので、近似では扱わない
- `BrushStyle.StyleFlag` のビット 0x40 は先端を 90° 回す（ti では水平の線が細く垂直の線が太くなり、te ではどの向きの線も太くなる。インクの総量は同じ）。丸い先端（b）では画素が変わらない。
  ひな形の値は 0x1c600 で、コーパスでは 0x1c048・0x1c04c・0x1c000・0x1c058・0x1d008 が多い。0x200・0x400 は効かず、0x08 はインク 0.3%。0x10 を立てた試験ファイルは CSP が開くときに落ちた
- 保存画素を消した作品の複製（src_bc）を CSP は描き直し、その書き出しは元の保存画素と全画素で一致した。大きさの曲線を直線にすると（src_bl）インクは 3.3 倍になり、CSP はその曲線（`MainId` で指すもの）を使っている。
  保存画素は今の CSP がベクターデータから描いたものとみなせる。ただし移した窓の保存画素にはほかのブラシの線も入るので、移した線の比べは CSP の書き出しどうしで行う

| tz_b、大きさ・不透明度の乱数の倍率を入れた後 | 1.26 | | |
| tz_b、向きの乱数を上の規則にした後 | 1.17 | 0.73 | 23.7 dB |
| tz_b_ro（向きの乱数を外したもの） | 1.14 | 0.76 | 24.1 dB |

残る差は線の端（CSP の端の方が細く短い）。コーパス全体（30 MB 未満の 531 作品のうち、ベクターレイヤーに画素も保存された 159 枚）の保存画素との比べでは、
インクの比の中央値が 1.33 → 1.08、重なりの中央値が 0.70 → 0.79 になった（先端の形 1.27、スプライン 1.28、速度 1.22、半径ごとのアンチエイリアスの減り 1.13、StyleFlag 0x40 1.10、乱数の倍率と向きの乱数 1.08）。
細い楕円の減りの規則は、共通の 132 枚でインクの比の |log| の平均を 0.135 → 0.127 にした（中央値は 1.07 のまま）。
大きさの影響が筆圧だけ（0x11、66 枚）の線は 1.23 → 1.01（重なり 0.80）、乱数つき（0x91、14 枚）は 1.26 → 1.12。残る太すぎは速度だけ（0x41、8 枚）の 1.68 と 0x101（2 枚）の 1.96。
tz_a では同じデータを CSP と 1.03 で描けるので、0x41 の差は移していない設定にある。0x41 の 3 作品のブラシと tz_a の行を比べると、違いは
画像の先端（`PatternStyle` 1・2、`TexturePattern`）、紙質（`TextureFlag`・`TextureScale` など）、デュアルブラシ（`DualStyleIndex`）、ブラシ濃度の影響（`FlowEffector` 0x51）と `StyleFlag` 0x10 だけだった。
これらは描かないもの（要求 4 章）なので、0x41 の差は近似の対象外の差とする。コーパスの 320 行では `StyleFlag` 0x10 と `PatternStyle` > 0 が完全に一致し、0x10 は画像の先端を使う印とみられる（模様の表のない試験ファイルで 0x10 を立てると CSP が落ちたことと合う）

## 再現の手順

```sh
# CSP で blend_modes.clip を作る（上の「作ったファイル」の通り）
cargo run --release --example blend_test -- blend_modes.clip blend_test.clip
# blend_test.clip を CSP で開き、「画像を統合して書き出し → .png」で csp.png を書き出す
cargo run --release --example blend_compare -- blend_test.clip csp.png

# 5 章（パターンの PNG は何でもよい）
cspf new attr.clip --size 512x512 --image pattern512.png
cspf add-layer attr.clip grad200.png a1.clip --name 乗算50 --at 40,40
cspf set a1.clip 5 a2.clip --opacity 50 --blend 2        # 以下、clip.clip も同様に作る
# CSP で開いて書き出し → attr_csp.png
cargo run --release --example render_compare -- attr.clip attr_csp.png

# 6 章（effects_tmpl.clip は 4 章のひな形）
cargo run --release --example tone_test -- effects_tmpl.clip tone_a.clip
cargo run --release --example tone_test -- effects_tmpl.clip tone_b.clip b
# CSP で開いて書き出し → tone_a_csp.png、tone_b_csp.png

# 7 章（vec_tmpl.clip は CSP の G ペンで線を引いたファイル）
cargo run --release --example vec_test -- vec_tmpl.clip vec_a.clip a     # a〜m、z、ta〜tj
# CSP で開いて書き出し → vec_a.png。このライブラリの描画は cspf render vec_a.clip ours.png --scale 1
cargo run --release --example vec_transplant -- vec_tmpl.clip WORK.clip LAYER tx.clip    # tx.clip.moved.png がこのライブラリの描画
cargo run --release --example vec_clear -- vec_ti.clip 4 f40_ti.clip "UPDATE BrushStyle SET StyleFlag = StyleFlag | 64"
VC_SEED=1 cargo run --release --example vec_clear -- tq_s.clip 4 dr_r.clip \
  "UPDATE BrushStyle SET ThicknessBase = 0.51, ThicknessEffector = X'00000001', RotationBase = 181.5, RotationEffector = 195, RotationRandom = 0.3"
cargo run --release --example vec_draw -- f40_ti.clip ours.png    # 保存画素を使わずベクターデータから描く
```
