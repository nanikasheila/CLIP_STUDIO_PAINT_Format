# W1 実ファイルでの検証（2026-10-25）

`cspf asset corpus ROOT OUT.jsonl` を、PC 上の実ファイルのコピー 3 か所で実行した結果です。
ファイルの中身・パス・名前は記録せず、件数だけを記します（C2、NA1）。

**267 件すべて合格（失敗 0）。** 名前から形式が分からないファイルは 0 件（空ファイルを除く）。

### 見つかったこと

- **孤立ノード**: ユーザーのツール DB に、どこからも参照されない消しゴムのノードが 1 つあった（CSP 自身が残したもの）。
  壊れているわけではないので、ツリーの検査では数を報告するだけにした（A3 の受入基準を修正）。
- **`webWhiteList.xml`** は拡張子が `.xml` でも中身は C2F（暗号化）。名前の表で区別する。
- **`.sut` の tar** は CSP 独自の形（モード 0777、所有者 `compress`、チェックサムは 7 桁と NUL、全エントリーが素材データの更新時刻）。
  同じ形で書くと、書き出した `.sut` の同梱素材がバイト一致する。`description.tar` も同じ形。

## 抽出の再現（A6 の一部）

CSP が書き出した `.sut` から、`cspf asset sut-extract` で同じサブツールをもう一度抜き出し、元のファイルと比べた。
素材は `.sut` から取り出した素材フォルダー（CSP の素材フォルダーと同じ並び、`catalog.xml` など `.sut` に入らないファイルも置く）から探させた。

| 表 | 結果 |
|---|---|
| `Manager` | 全列一致 |
| `Node` | 全列一致（ツール DB の素材列 `NodeMaterial*` は除く、CSP の `.sut` と同じ） |
| `Variant` | 2 行とも全値一致。列は CSP の 127 列に対して 126 列（CSP は値が全行 NULL の `BrushSprayFixedPointArray` 列も残していた） |
| `MaterialFile` | 2 行とも全列一致。`FileData`（素材の tar）はバイト一致 |

CSP がどの基準で値のない列を残すかは未解明。CSP での読み込み（W3）で影響がないかを確かめる。

## 再現の手順

```sh
cargo build --release -p cspf
cspf asset corpus <設定フォルダーのコピー> settings.jsonl
cspf asset corpus <既定データのコピー> defaults.jsonl
cspf asset corpus <素材フォルダーのコピー> materials.jsonl
```

結果の JSONL はファイルごとに 1 行（相対パス、系統、形式、検査の結果）。パスを含むのでリポジトリには入れない。
