# 要求仕様: CSP のその他の独自形式（サブツール・オートアクション・カラーセットなど）

**版**: 1.0（2026-10-25）
**状態**: 承認済み（開発の委任に基づく）

[docs/requirements.md](../requirements.md) が `.clip` / `.cmc` を扱うのに対し、この文書は CLIP STUDIO PAINT（CSP）が
作品以外に使う独自形式（ペン・ブラシなどのサブツール、オートアクション、カラーセット、グラデーションセット、
ワークスペースや各種設定、素材の目録）を**解析し尽くし、検証し、再利用できる形で配布する**ための要求です。
受入基準と検証方法を付け、`docs/assets/validation/` の記録で満たしたかを追跡します（末尾のトレーサビリティ表）。

---

## 1. 背景と目的

- name-studio（`crates/clip-core/src/subtool.rs`）は、ネームを描くのに必要な範囲だけ `.sut` とツールのデータベースを読んでいる
  （大きさ・不透明度・入り抜き・筆圧の影響元・ブラシ先端の画像など、約 20 項目）。書き出しはできない。
- そのほかの形式（オートアクション、カラーセット、グラデーション、ワークスペース、素材）は手付かず。
- ユーザーが共有・配布するのはこれらの形式（.sut、.las、.cls など）であり、ツールから読めて書けると、
  ブラシの一覧・比較・一括調整・移植・バックアップの検査などに使える。

目的は次のとおり。

1. **全解析**: 形式ごとの構造（テーブル・列・バイナリ・直列化）を目録にし、意味が分かったものと分からないものを区別する
2. **検証**: PC 上の実ファイル（ユーザーの設定・CSP 同梱の既定データ・素材）で、読み取りと書き戻しの正しさを機械的に確かめる
3. **再現**: CSP が読み込めるファイルを書き出せる（編集・抽出・新規作成）。書いたファイルを CSP で読み込んで確かめる
4. **再利用**: 用途に依存しないライブラリ・CLI・Python・仕様書として配布する

## 2. 前提と制約

- **C1 入力は読み取り専用**。CSP の設定フォルダ・インストール先・素材フォルダのファイルは決して書き換えない。
  調べるときは作業用のコピーを使う。
- **C2 実ファイルはリポジトリに入れない**。ユーザーの設定・素材・CSP 同梱データ（CELSYS の著作物）は、集計だけを記録する。
  テストは合成したファイルを使う。
- **C3 公式仕様がない**。記述ごとに確度（確認済み / 推測 / 未解明）と根拠を付ける。
- **C4 CSP 本体の判定が最終的な正解**。書き出したファイルは CSP で読み込んで確かめる（PC の操作。ほかのスレッドと
  `cspcheck\csp_lock.txt` で順番を取る）。
- **C5 暗号化された素材は復号しない**。CSP の素材（`.layer` / `.tool` / `.pose` など、目録で `encrypt="true"`）の中身は
  CELSYS が暗号化している。復号は技術的保護手段の回避にあたるおそれがあるため対象外とし、外枠（チャンクの区切り）と
  平文の目録・サムネイルだけを扱う。

### 2.1 調べた実ファイル（2026-10-25）

| 場所 | 内容 |
|---|---|
| `%APPDATA%\CELSYSUserData\CELSYS\CLIPStudioPaintVer1_5_0` | ユーザーの設定 約 100 ファイル（ツール DB、オートアクション、カラーセット、ショートカットなど） |
| CSP のインストール先 `Settings\PAINT` | CSP 同梱の既定データ（言語別のツール DB・ブラシプリセット・オートアクション・カラーセット・グラデーション・ワークスペース） |
| `%APPDATA%\CELSYSUserData\CELSYS\CLIPStudioCommon\Material` | 素材 約 1,700 件（12,612 ファイル） |
| ユーザーの作業フォルダー | `.sut` 1 件 |

形式は 4 系統に分かれる。

| 系統 | 見分け方 | 形式 |
|---|---|---|
| SQLite | 先頭 `SQLite format 3\0` | `.sut` `.todb` `.bfps`（サブツール）、`.spws`（ワークスペース）、`.khc`（ショートカット）、`.tomd`、`.pcs`、`.tlbr` ほか約 40 種 |
| 型付き直列化 | 先頭 `01 01 01 08 "typename"` | `.laf` / `.las`（オートアクション）、`.sgs`（グラデーションセット） |
| SLCC | 先頭 `SLCC` | `.cls`（カラーセット） |
| C2F チャンク | 先頭 `89 "C2F" 0D 0A 1A 0A` | 素材の中身（暗号化）、`catalog.zip` など |

## 3. スコープ

| 区分 | 内容 | 扱い |
|---|---|---|
| 型付きで読み書き | サブツール（.sut / .todb / .bfps）、オートアクション、グラデーションセット、カラーセット | 読み・書き・検証 |
| 目録化して保持 | そのほかの SQLite 設定（ワークスペース、ショートカット、環境設定、ツールバーなど） | 表・列・型・値の範囲・意味を目録化。読み書きは汎用（ロスレス） |
| 平文だけ読む | 素材の目録（catalog.xml / info.xml / layerData.xml / .cac）、サムネイル、素材 DB | 読み取り |
| 対象外 | 暗号化された素材の中身、ブラシエンジンによる描画の再現、3D データ | 外枠だけ扱い、中身は不透明なバイト列として保持 |

## 4. 機能要求

優先度: **必須** / **推奨**。

### A1 形式の目録（必須）
CSP が使う設定・資産ファイルを、拡張子・場所・系統・用途の表にする。形式を判定する関数を持つ。
- 受入: 2.1 の全ファイル（空ファイルを除く）の系統が判定でき、「不明」0 件。用途の説明が全形式にある
- 検証: W1

### A2 SQLite 形式の汎用読み取りと目録（必須）
SQLite 系の全形式について、表・列・型・行数・観察された値の範囲を目録にする。
- 受入: 2.1 の全 SQLite ファイルを読める（エラー 0）。目録の全列に型と出現数がある
- 検証: W1、目録の自動生成

### A3 サブツールの構造（必須）
`.sut` / `.todb` / `.bfps` の `Manager` / `Node` / `Variant` / `MaterialFile` を読み、ツリー（ツール → グループ → サブツール）、
ノードの種類（`NodeInputOp` / `NodeOutputOp` / `NodeRangeOp`）、設定（Variant）、共通設定（`CommonVariantID`）、初期設定（`NodeInitVariantID`）、
同梱素材（`MaterialFile.FileData` の tar）を型付きで扱える。
- 受入: 全サンプルでツリーが閉じる（循環・欠落なし。どこからも参照されない孤立ノードは CSP 自身が残すことがあるので、数を報告する）。全サブツールの設定を読める
- 検証: W1、W2

### A4 サブツールのバイナリ列（必須）
`Variant` の BLOB 列（影響元設定 `*Effector`、ブラシ先端・紙質の画像列 `*ImageArray` / `*TextureImage`、`VariantShowParam`、
`BrushInOutTarget`、`GradationData`、`IncludeFillColor`、`ContourFillBlendGraph` など 32 列）と `Manager.PressureGraph` を解析する。
- 受入: 全サンプルの全 BLOB で「解析 → 直列化」が元のバイト列と一致する。未解読のフィールドは保持される
- 検証: W1

### A5 サブツール設定の意味（必須）
`Variant` の全列（約 530）について、CSP の画面での名前（ツールプロパティ / サブツール詳細の項目名）・単位・値の範囲・既定値を記す。
- 受入: 観察された全列に意味の記述があり、確度が付く。ペン・ブラシ・消しゴムで使う列（コア）はすべて「確認済み」か「推測」。
  主要な項目は CSP で 1 項目だけ変えて書き出した `.sut` の差分（W4）で確認済み
- 検証: W4、目録

### A6 サブツールの書き出し（必須）
`.sut` を書ける: ロスレスな書き戻し、設定の変更（名前・大きさ・不透明度・筆圧など）、ツール DB からの 1 サブツールの抽出、
新規作成（ひな形なし、または最小のひな形から）。同梱素材も扱う。
- 受入: 変更しない書き戻しで全表・全行が論理的に一致。書いた `.sut` を CSP で読み込め、変えた値がツールプロパティに表示される（W3）
- 検証: W2、W3

### A7 型付き直列化（必須）
`.laf` / `.las` / `.sgs` の直列化を、型（文字列・バイト列・真偽・整数・実数・配列・オブジェクト）ごとに読み書きする汎用の実装。
- 受入: 全サンプルで「解析 → 直列化」がバイト一致（末尾のごみは保持し、報告する）
- 検証: W1、W2

### A8 オートアクション（必須）
オートアクションセット（名前、アクション一覧、各アクションの項目・種類・パラメーター・有効/無効）を型付きで読み書きする。
- 受入: 全サンプルを読める。項目の種類（`actionItemKind`）の一覧と意味を記す。書いた `.laf` を CSP で読み込める（W3）
- 検証: W1、W3

### A9 グラデーションセット（必須）
グラデーションセット（セット名、グラデーション名、色の点・不透明度の点・位置・補間）を型付きで読み書きする。
`GradationData` はサブツールの `Variant.GradationData` や `.clip` のグラデーションと共通かを確かめる。
- 受入: 全サンプルを読める。データの全フィールドに意味がある。CSP の表示と色・位置が一致する（W3）
- 検証: W1、W3

### A10 カラーセット（必須）
`.cls`（SLCC）を読み書きする: セット名、色（RGB / 透明 / 名前付き）、色空間。
- 受入: 全サンプルを読み、バイト一致で書き戻せる。書いた `.cls` を CSP で読み込め、色と名前が一致する（W3）
- 検証: W1、W3

### A11 素材の目録（推奨）
素材フォルダの `catalog.xml` / `info.xml` / `icedata/layerData.xml` / `.cac`、素材 DB、サムネイルを読み、素材の一覧
（名前・種類・タグ・作成日・サムネイル・データファイル）を作る。C2F チャンクの外枠を解析する。
- 受入: 全素材フォルダを読める（エラー 0）。暗号化されたデータは復号せず、そのことを結果に示す
- 検証: W1

### A12 ワークスペース・ショートカットなど（推奨）
`.spws`（ワークスペース）、`.khc`（ショートカット）、`.tomd`（修飾キー）、ツールバー、環境設定を、目録と意味の記述付きで読める。
- 受入: 主な表の列に意味がある。ショートカットはコマンド名とキーの組として読める
- 検証: W1

### A13 道具（CLI）（必須）
`cspf asset` 以下に、`kind`（形式の判定）、`inspect`（JSON で要約）、`subtools`（サブツール一覧）、`sut-extract`（DB から .sut を抽出）、
`sut-set`（設定の変更）、`dump`（型付き直列化を JSON に）、`colorset`（.cls と JSON の相互変換）、`catalog`（素材一覧）、`corpus`（全件の検査）を持つ。
- 受入: 合成ファイルでのテスト（W2）

### A14 Python から使える（推奨）
標準ライブラリだけで、サブツール・型付き直列化・カラーセット・素材の目録を読める。
- 受入: Rust 版と同じサンプルで同じ結果（W5）

## 5. 非機能要求

`.clip` 側の N1〜N7 に従う。加えて:

| ID | 要求 | 受入基準 |
|---|---|---|
| NA1 プライバシー | ユーザーの設定にはファイルのパス（最近使ったファイル）やログイン情報がある。集計・報告にそれらを含めない | 集計ツールは構造と値の範囲だけを出力し、文字列の値は出さない |
| NA2 安全な読み取り | CSP が開いている DB を直接開かない | ファイルをメモリに読み込んでから開く |

## 6. 検証の方法

| ID | 方法 | 内容 |
|---|---|---|
| W1 | 実ファイルでの検証 | PC 上の全サンプル（2.1）で `cspf asset corpus` を実行し、A1〜A4・A7〜A11 の判定を集計。集計を `docs/assets/validation/` に記録 |
| W2 | 単体テスト | 合成ファイルによる自動テスト（CI） |
| W3 | CSP での確認 | 書いたファイルを CSP で読み込み、画面で値を確かめる（PC の操作）。手順と結果を記録 |
| W4 | 差分による意味の確定 | CSP で 1 項目だけ変えたサブツールを書き出し、変わった列と値を記録 |
| W5 | 実装間の比較 | Python 版と Rust 版、name-studio の `subtool.rs` と結果を比べる |

## 7. 完了の定義

- 必須要求（A1〜A10、A13）の受入基準を満たし、`docs/assets/validation/` に根拠がある
- 仕様書（`docs/assets/spec/`）が目録と一致し、未解明の項目は一覧になっている
- CI が緑で、main にマージされている
