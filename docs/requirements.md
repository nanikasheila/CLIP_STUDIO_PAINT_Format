# 要求仕様: CLIP STUDIO PAINT ファイル形式ライブラリ

**版**: 1.0（2026-10-24）
**状態**: 承認済み（開発の委任に基づく）

この文書は、CLIP STUDIO PAINT（以下 CSP）の `.clip`（1 枚のキャンバス）と `.cmc`（複数ページ作品）を
**解析し尽くし、検証し、再現できる**ライブラリを作るための要求です。各要求には受入基準と検証方法を付け、
`docs/validation/` の報告で満たしたかどうかを追跡します（末尾のトレーサビリティ表）。

---

## 1. 背景と目的

CSP の形式は公開されていません。これまで 2 つのリポジトリで、それぞれの用途に必要な範囲だけを解析してきました。

| リポジトリ | 実装 | 解析した範囲 |
|---|---|---|
| csp-name-splitter | Python（`name_splitter/csp`） | コンテナ、Canvas / Layer、ラスター、ベクター、テキスト、.cmc。形式メモ `docs/formats/csp-file-format.md` |
| name-studio | Rust（`crates/clip-core`） | 上記の移植と拡張（見開き、書き出しの自己確認、サブツール .sut） |

どちらも「ネーム」の用途に結び付いており、ほかのツールから使いにくく、解析の根拠（どのファイルで確かめたか）も散らばっています。
このリポジトリでは次を目的とします。

1. **全解析**: ファイルに現れる構造（チャンク、テーブル、列、バイナリ）をすべて目録にし、意味が分かったものと分からないものを区別して記す
2. **検証**: 実ファイルの大きな集合（コーパス）に対して、読み取り・書き戻し・再エンコード・描画の正しさを機械的に確かめる
3. **再現**: CSP が開けるファイルを書き出せる（編集・新規作成）。書いたファイルを CSP で開いて確かめる
4. **再利用**: 用途に依存しないライブラリ・CLI・仕様書として配布し、既存の 2 リポジトリもこれを使えるようにする

## 2. 利害関係者と利用場面

| 利害関係者 | 利用場面 |
|---|---|
| name-studio（Rust アプリ） | ネームの .clip 読み込み、ページの .clip / .cmc 書き出し、セリフの読み戻し |
| csp-name-splitter（Python ツール） | ネーム用紙の分割、ページ書き出し |
| 第三者のツール開発者 | レイヤー画像の取り出し、サムネイル、変換（PNG など）、一括処理 |
| 形式の研究者 | 仕様書・スキーマ目録・調査ツールで未解明部分を調べる |
| 作者（ユーザー） | 自分の作品ファイルを壊さずに扱えること |

## 3. 前提と制約

- **C1 入力は読み取り専用**。元ファイルは決して書き換えない（出力は必ず別のパス）。
- **C2 作品はリポジトリに入れない**。実ファイルは作者の作品であり、コーパスはユーザーの PC に置いたまま調べる。
  リポジトリに入れてよいのは、作品の中身（画素・文字・レイヤー名）を含まない集計結果だけ。テストは合成ファイルを使う。
- **C3 公式仕様がない**。すべての記述は観察に基づく。記述ごとに確度（確認済み / 推測 / 未解明）と根拠（何件のファイルで確かめたか）を付ける。
- **C4 CSP 本体の判定が最終的な正解**。書き出したファイルが正しいかは、最終的に CSP で開いて確かめる（PC の操作で行う）。
- コーパス（2026-10-24 時点）: `.clip` 719 件、`.cmc` 42 件、`.sut` 1 件、計 24.7 GB。保存日 2017-08〜2026-10。

## 4. スコープ

対象: `.clip`（CSFCHUNK コンテナ + SQLite + 外部チャンク）、`.cmc`（SQLite）。付録として `.sut`（サブツール、SQLite）。

| 区分 | 内容 | 扱い |
|---|---|---|
| 解析・型付きで扱う | コンテナ、スキーマ登録（ParamScheme / ElemScheme）、Project、Canvas、Layer ツリーと属性、ラスター画素（カラー・グレー・2値・マスク）、ミップマップ、サムネイル、プレビュー、ベクター、テキスト、作品（.cmc） | 読み・書き・検証 |
| 目録化して保持する | 定規、3D、タイムラプス、アニメーション、ブラシ設定、レイヤーカンプなど上記以外のテーブル | 列の型・値の範囲・リンクを目録化。中身は手を加えずそのまま保持（ロスレス） |
| 対象外 | CSP のブラシエンジンによるベクター線の厳密な描画、3D モデルの描画、色管理（ICC）の厳密な再現 | 近似で描くか、描かない（理由を仕様書に記す） |

## 5. 機能要求

優先度: **必須**（完了の条件）/ **推奨**（できる限り行う）。

### R1 コンテナの読み取り（必須）
CSFCHUNK のヘッダー・チャンク列（Head / Exta / SQLi / Foot）を読み、外部チャンクを ID で引ける。
- 受入: コーパスの全 `.clip` で、宣言サイズとファイルサイズの一致、チャンク列の終端、`ExternalChunk.Offset` とチャンク位置の一致を確認できる
- 検証: コーパス検証（V1）

### R2 データベースの汎用的な読み取り（必須）
埋め込み SQLite のすべてのテーブル・行・列を、列が無い場合も含めて読める。
- 受入: コーパスの全ファイルで全テーブルを読める（エラー 0 件）
- 検証: V1

### R3 スキーマ目録（必須）
ファイル自身が持つスキーマ登録（`ParamScheme`: テーブル・列・データ型・リンク先、`ElemScheme`: 要素の種類・最大 ID、
`ExternalTableAndColumnName`: 外部チャンクを持つ列）を読み、コーパス全体の和集合を目録にする。
- 受入: 目録のすべての列に、型・リンク先・出現件数・観察された値の範囲と、意味の記述（確認済み / 推測 / 未解明）がある。
  コア領域（R4〜R10）の列はすべて「確認済み」か「推測」
- 検証: 目録の自動生成と網羅率の集計（V2）

### R4 型付きのモデル（必須）
Project、Canvas（大きさ・単位・解像度・トンボ・作品情報）、Layer ツリー（種類、表示、不透明度、合成モード、クリッピング、ロック、
マスク、オフセット、フォルダーの開閉など）を型付きで読める。.cmc のページ一覧（連結リスト）を読める。
- 受入: コーパスの全ファイルでツリーが閉じる（循環・未参照・欠落なし）。種類の判定が全レイヤーで付く（「不明」は理由付きで報告）
- 検証: V1、合成ファイルの単体テスト（V5）

### R5 ラスター画素の復号（必須）
Offscreen の画素（カラー / グレー / 2値 / マスク、ミップマップの各段）を復号できる。
- 受入: コーパスの全ブロックでチェックサム（Adler-32）が一致し、すべての Offscreen を復号できる
- 検証: V1

### R6 ラスター画素の符号化（必須）
画素から Offscreen のブロックデータ・属性・チェックサムを作れる。
- 受入: コーパスの全 Offscreen について「復号 → 符号化 → 復号」で画素が一致し、チェックサムが正しい。
  さらに、CSP と同じ圧縮で元のバイト列と一致する割合を報告する（推奨: 99% 以上）
- 検証: V1

### R7 ベクターデータ（必須）
`VectorObjectList.VectorData` を解析し、点・外接矩形・色・太さ・フラグを読み書きできる。
- 受入: コーパスの全ベクターで「解析 → 直列化」が元のバイト列と一致する。未解読のフィールドは保持される
- 検証: V1

### R8 テキストデータ（必須）
テキストレイヤーの本文と属性 TLV（`TextLayerAttributes` / `…Array`）を読み書きできる。
- 受入: 全テキストで「解析 → 直列化」が元と一致。既知の ID（フォント、大きさ、外接矩形、色など）を型付きで読める
- 検証: V1

### R9 サムネイル・プレビュー（必須）
`CanvasPreview`（PNG）、`LayerThumbnail`、.cmc のページサムネイルを取り出せる。
- 受入: 全ファイルでプレビューを PNG として復号できる
- 検証: V1

### R10 合成描画（必須）
レイヤーを CSP と同じ規則（表示、不透明度、合成モード、クリッピング、レイヤーマスク、フォルダーの通過）で重ね、キャンバス全体の画像を作れる。
- 受入: CSP 自身が保存したプレビュー（`CanvasPreview`）と、同じ大きさに縮めた描画結果を比べ、
  ベクター・テキスト・3D・調整レイヤーを含まないファイルの 90% 以上で PSNR 30 dB 以上。合成モードごとの対応表を仕様書に載せる
- 検証: プレビューとの比較（V3）

### R11 ロスレスな書き戻し（必須）
読み込んだファイルを変更せずに書き出すと、元と同じバイト列になる。変更したテーブル・チャンクだけが変わる。
- 受入: コーパスの全ファイルでバイト一致
- 検証: V1

### R12 編集と書き出し（必須）
既存ファイルを元に、レイヤーの画素の差し替え、ラスターレイヤーの追加・削除、属性（名前・表示・不透明度・合成モードなど）の変更をして保存できる。
保存時に ID の採番（ElemScheme）、外部チャンクの位置、ミップマップ・サムネイル・プレビューの整合を保つ。
- 受入: 書き出したファイルが自己整合性検査（V4）を通り、CSP で開ける（V6 の手順書の全ケース）
- 検証: V4、V6

### R13 新規作成（必須）
CSP のひな形ファイルなしで、指定した大きさ・解像度のキャンバスとラスターレイヤーを持つ `.clip` を作れる。
- 受入: V4 を通り、CSP で開ける（V6）。CSP で開いて保存し直したファイルとの構造差分を報告する
- 検証: V4、V6

### R14 作品（.cmc）の読み書き（必須）
ページ一覧・作品設定を読み、ページの追加・並べ替えをした .cmc を書ける。
- 受入: コーパスの全 .cmc でページの連結リストが閉じ、リンク先のページファイルが解決できる（存在しないものは報告）。書いた .cmc を CSP EX で開ける（V6）
- 検証: V1、V6

### R15 道具（CLI）（必須）
`inspect`（構造の要約）、`schema`（スキーマ目録）、`layers`（レイヤー一覧）、`extract`（レイヤー画像の PNG）、
`render`（合成画像）、`preview`（保存されたプレビュー）、`verify`（自己整合性）、`roundtrip`（書き戻し検証）、`corpus`（コーパス検証の集計）を持つ。
- 受入: 各コマンドの合成ファイルでのテスト（V5）

### R16 Python から使える（推奨）
Python の標準ライブラリだけで動く読み取り実装か、Rust 実装の Python バインディング。
- 受入: csp-name-splitter の読み取りを置き換えられる

## 6. 非機能要求

| ID | 要求 | 受入基準 |
|---|---|---|
| N1 安全性 | 壊れた・悪意のある入力でもパニック・無限ループ・過大な確保をしない | `unsafe` は CSP と同じ圧縮のための zlib 呼び出し（`zlib.rs`）だけ。境界検査。合成した壊れたファイルのテストとファジング（推奨） |
| N2 性能 | A3 600dpi（約 7000×10000 px）のページのレイヤー画像を 1 秒程度で復号 | ベンチマークで報告 |
| N3 移植性 | Windows / Linux / macOS | CI で Linux と Windows |
| N4 依存の少なさ | 中核は SQLite・zlib・PNG だけに依存 | Cargo の依存を確認 |
| N5 追跡可能性 | 仕様の記述ごとに確度と根拠（件数）を持つ | 仕様書の書式で担保 |
| N6 プライバシー | コーパス由来の報告に作品の中身を含めない | 集計ツールは構造だけを出力 |
| N7 ライセンス | MIT | LICENSE |

## 7. 検証の方法

| ID | 方法 | 内容 |
|---|---|---|
| V1 | コーパス検証 | ユーザーの PC 上で全実ファイルに対して CLI の `corpus` を実行し、R1〜R9・R11・R14 の判定を集計する。集計（作品の中身を含まない）を `docs/validation/` に記録 |
| V2 | スキーマ目録の網羅率 | ParamScheme の和集合に対して、意味の記述がある列の割合を集計 |
| V3 | 描画の比較 | `CanvasPreview` と描画結果の PSNR。合成モード・レイヤー種類別に集計 |
| V4 | 自己整合性検査 | 書いたファイルを読み直し、チャンク位置・ID 採番・リンク・ツリー・チェックサム・ミップマップの段数と大きさを検査（`verify`） |
| V5 | 単体テスト | 合成ファイル（コーパスで観察した構造の最小構成）による自動テスト。CI で実行 |
| V6 | CSP での確認 | 書き出したファイルを PC の CSP で開き、画面とレイヤーパレットを確かめる（PC の操作）。手順と結果を `docs/validation/` に記録 |
| V7 | 実装間の比較 | 既存の Python 版・Rust 版（clip-core）と同じファイルで読み取り結果を比べる |

## 8. 完了の定義

- 必須要求（R1〜R15）の受入基準をすべて満たし、`docs/validation/` に根拠がある
- 仕様書（`docs/spec/`）がスキーマ目録と一致し、未解明の項目は一覧になっている
- CI が緑で、main にマージされている
- 既存リポジトリ（name-studio / csp-name-splitter）から使うための移行方法が書かれている
